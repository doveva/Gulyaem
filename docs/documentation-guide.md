# Правила документации

## Основные принципы

Документация является частью изменения продукта, а не отдельным этапом после реализации.

1. Общие решения хранятся в `docs/`.
2. Каждый логический модуль с кодом имеет `README.md` в корне модуля.
3. Вложенные технические каталоги не обязаны иметь собственный README, если их назначение
   полностью раскрыто в README родительского модуля.
4. Изменение поведения модуля требует обновления ближайшего README в том же дереве каталогов.
5. Значимое архитектурное решение оформляется отдельным ADR.
6. Долг, обнаруженный при реализации, заносится в общий реестр, если его нельзя устранить в
   рамках текущего изменения.
7. Перед началом этапа создаётся отдельный комплект Stage-документации; после завершения он
   обновляется фактическими результатами.

## Что должно быть в README модуля

Минимальная структура:

```markdown
# Название модуля

Коротко: зачем модуль существует и за что отвечает.

## Ответственность

## Границы и зависимости

## Основные сценарии

## Структура

## Запуск и проверка

## Конфигурация

## Ограничения и технический долг

## Связанные документы
```

README описывает назначение и поведение модуля. Он не должен пересказывать код построчно или
превращаться в журнал каждого рефакторинга.

## Когда README нужно менять

README обновляется, если изменение затрагивает хотя бы один пункт:

- ответственность или границы модуля;
- публичный API, события или формат данных;
- ключевой пользовательский или фоновый сценарий;
- зависимость от другого модуля или внешней системы;
- конфигурацию, запуск, миграцию или эксплуатацию;
- важное ограничение, риск или технический долг.

Для форматирования, переименования локальной переменной и правки теста без изменения поведения
обновление документации не требуется.

## Общая документация

| Изменение | Где документировать |
|---|---|
| Архитектура системы или границы модулей | `docs/architecture/` |
| Новое значимое решение с альтернативами | `docs/adr/` |
| Сборка, окружение, деплой, rollback, эксплуатация | `docs/deployment/` |
| Отложенная проблема или осознанный компромисс | `docs/technical-debt/` |
| Product scope и устойчивые доменные понятия | `docs/product/` |
| Требования и результат этапа | `docs/stage N/` |

## Документация этапа

Каталог этапа называется `docs/stage N/` и имеет собственный `README.md`. Рекомендуемый набор:

- `stage-N-requirements.md` — цели, scope и требования;
- `architecture-contract.md` — зафиксированные технические границы;
- `implementation-plan.md` — последовательность реализации;
- `acceptance-criteria.md` — проверяемые критерии завершения;
- `open-decisions.md` — вопросы, которые этап должен закрыть;
- итоговый отчёт или принятые ADR — по завершении этапа.

Шаблон точки входа находится в [`stages/stage-template.md`](stages/stage-template.md).

## Общий индекс

Генератор изменяет только блоки между `docs:index:start` и `docs:index:end`. Остальной текст
`README.md` и `docs/README.md` остаётся ручным.

Обновить индекс:

```bash
python3 scripts/docs/docs.py index
```

Проверить, что индекс актуален, ничего не меняя:

```bash
python3 scripts/docs/docs.py index --check
```

## Проверка связи кода и README

Проверить незакоммиченные и подготовленные изменения:

```bash
python3 scripts/docs/docs.py check
```

Проверить накопленный diff ветки относительно базовой ветки:

```bash
python3 scripts/docs/docs.py check --base main
```

Расширения кода и исключения задаются в [`docs/docs-config.json`](docs-config.json). Для
вложенного файла корневой README репозитория не считается документацией модуля: в дереве файла
должен существовать хотя бы один более близкий `README.md`.

Пока проверка запускается локально. При подключении GitLab CI эти же команды должны стать
блокирующим job без изменения правил.

## Чек-лист изменения

- [ ] Обновлён README изменённого модуля.
- [ ] При необходимости обновлена общая архитектура или deployment-документация.
- [ ] Значимое решение зафиксировано в ADR.
- [ ] Новый технический долг добавлен в реестр.
- [ ] Индекс пересобран и проходит `index --check`.
- [ ] Проверка `check` проходит для текущего diff.
